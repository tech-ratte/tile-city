# 達人 Bot（master）設計書

実装の仕様ソース。`js/game/bot.js` / `js/game/botMaster.js` と対応する。

## スコープ

| 項目 | 内容 |
|------|------|
| レベル | `master` |
| 基盤 | `standard` ヒューリスティック |
| 主目的 | 仮想得点差（自分見込み − 脅威相手見込み）を最大化 |
| やること | 閉じやすさ、脅威付き妨害、同乗/独占/閉じない、ミープル拘束、追加定石 |
| やらないこと | MCTS、山札順序の完全利用、同一フィーチャーへのミープル積み増し |

## 脅威度 `threat(p) ∈ [0,1]`

```
threat(p) = clamp01(
  0.45×点差・順位の危うさ
+ 0.35×自由ミープル比率
+ 0.20×大きい未完成の有無
− 0.15×拘束ミープル数
)
threat はフェーズで減衰（early×0.2 / mid×0.65 / late+×1）
threat < 0.45 → 妨害オフ寄り
```

妨害・解放系は対象フィーチャーの多数派相手について **× threat(p)**。  
**閉じにくくする／大きくする罰は敵単独多数の都市にのみ適用**（自分sole・自分との同数相乗りには掛けない）。  

**妨害の優先度を下げるのは「一手で大きく独占完成できるとき」だけ**（`immSelf ≥ bigSelfFinishAt` かつ相手0点、既定8）。そのターンは early 妨害オフ＋`denialCap`（既定4.5）。それ以外は脅威ゲート付きで妨害を通常評価し、上限は `denialCapLoose`（既定11）。  
共有完成忌避は **独走（+12点差以上）のときだけ** 弱めに適用。

### 閉じやすさ（山札・ターン意識）

「完成させられる札があるか」だけでなく、残り置き順を分けて見る。

| 経路 | 内容 |
|------|------|
| 自分 | 自分の残りターンで有用札を引き、自分で置いて閉じる |
| 相手 | 得点受益者の相手が、自分の得のためにその札で完成させる |

`P_close = 1 − (1−P_self)(1−P_opp)`（二項近似、必要枚数≈min(開口,3)）。  
硬度の山札成分は `1 − P_close`。種類（カタログ）不能は従来どおり別枠で max 合成。

## 評価骨格

```
V = A（得点・完成）
  + B（自分の閉じやすさ）
  + C（脅威付き妨害の純益）
  + D（接続）
  + E（同乗 / 独占 / 閉じない）
  + F（ミープル拘束）
  + G（追加定石）
```

符号: 正＝加点、負＝減点。`V += 重み × 量`。

## 決定ルール

1. 非脅威への妨害はほぼ0 → 自分の得優先  
2. 妨害は純益 > 0 かつ脅威相手のみ  
3. 種類不能 > 残り札。大きくするだけは捨てる  
4. 独走相手の同数大完成は E3。E4 が大きいなら閉じる
