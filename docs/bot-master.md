# 達人 Bot（master）設計書（v3）

実装: `js/game/bot.js` / `js/game/botMaster.js`。  
方針: **ルール上の得点タイミングに忠実**にし、固定ゲートより **状況（残り自分手番・位相差・閉じ可能性）で係数を滑らかに変える**。

---

## 1. このゲームの得点ルール（実装どおり）

| 対象 | 完成時 | 終了時（未完成） | ミープル |
|------|--------|------------------|----------|
| 都市 | `(タイル+旗)×2` | `(タイル+旗)×1` | 完成で返還 |
| 道 | `タイル×1` | 同じ | 完成で返還 |
| 修道院 | `9` | `3×3の枚数` | 完成で返還 |
| 畑 | （なし） | `完成都市×3` | 返還なし |
| 多数派 | 単独が全点。同数はそれぞれ全点 | 同左 | 同一フィーチャーに追加置きは不可 |

山札が尽きたら終了処理。**手番が回ってこないミープルは終了点にしか使えない**。

---

## 2. 洗い出した判断パターン

### A. 完成（即時点＋ミープル回収）

| ID | 状況 | 望ましい挙動 |
|----|------|----------------|
| A1 | 自分sole都市/道を今閉じられる | 原則取る（都市は×2が効く） |
| A2 | 修道院を9点にできる | 取る |
| A3 | 閉じると敵だけ大得点 | 避ける（`enemyCompleteGift`） |
| A4 | 同数相乗りで両方大得点 | 自分がビハインドなら可、独走相手なら渋い |
| A5 | 小さい完成でミープル回収 | 残ミープルが少ないほど良い |

### B. 未完成の終了点・畑

| ID | 状況 | 望ましい挙動 |
|----|------|----------------|
| B1 | あと自分の手番が来る | 閉じられる見込みの都市を厚く、不能都市にミープルを縛らない |
| B2 | **あと自分の手番が来ない** | 温存罰をゼロ。終了点・畑にミープルを振る |
| B3 | 畑・完成都市≥1 | 終盤／ラストで候補に入れる（固定 `stock≥2` 禁止はしない） |
| B4 | 畑・完成都市0 | 置かない（0点） |
| B5 | 道は完成＝終了同点 | 閉じ優先度は都市より低くてよい |

### C. 閉じ可能性（L2）

| ID | 状況 | 望ましい挙動 |
|----|------|----------------|
| C1 | カタログに開口を埋める札が無い | `impossible`。新規拘束は大きく減点（手番が残るとき） |
| C2 | セットにはあるが山に無い | 同様に閉じ不可 |
| C3 | 残山で閉じられる | `P_close` で期待点をスケール |
| C4 | 開口が敵タイルで物理ブロック | `impossible` |

### D. 合流・妨害

| ID | 状況 | 望ましい挙動 |
|----|------|----------------|
| D1 | 大型に多数派／同数で乗れる | 加点 |
| D2 | 敵soleに大型を渡す | 減点 |
| D3 | 得点ビハインド | `lag` に応じ閉じ阻害を加点 |
| D4 | 互角以上 | 妨害はほぼ0 |
| D5 | 敵を大きくするだけで閉じられうる | 減点 |

### E. ミープル経済

| ID | 状況 | 望ましい挙動 |
|----|------|----------------|
| E1 | 手番が多く残ミープル少 | 使うコスト大（温存） |
| E2 | ラスト手番 | 使うコスト0。タイブレークも使用優先 |
| E3 | 今完成して返還 | コスト実質0 |

## 3. 状況変数

```
turnsAfter = この手のあと自分に回ってくる山札枚数（順番無視の席配分）
lastTurn   = turnsAfter ≤ 0
lag        = clamp01( (先頭相手点 − 自分点) / lagRef )
P_close    = L2（向き付き開口 × カタログ／残山）の2経路確率
```

ハード禁止は最小限（畑0点・物理不能のみ）。他は係数で抑える。

---

## 4. 評価式

```
V = V_std(状況で温存・畑コストが変化)
  + V_ev          # 期待点（完成見込みと終了点）
  + V_join
  + V_deny(lag)
  + V_minor
```

### 4.1 V_std の状況化

| 項 | 通常 | lastTurn |
|----|------|----------|
| `stockPenalty` | 残数に応じ 0〜2.5、かつ `× min(1, turnsAfter/3)` | **0** |
| 畑候補 | 完成都市とフェーズで抑制 | 完成都市≥1なら **常に候補** |
| `endSelf` | 1.0 倍（end フェーズは 1.15） | **×1.5** |
| タイブレーク | stock 多い方 | **stock 少ない方（使う）** |

### 4.2 V_ev（都市・道）

```
completePts(city) = size×2   # size=タイル+旗
endPts(city)      = size
completePts(road) = size
endPts(road)      = size

EV = P_close × completePts + (1−P_close) × endPts

自分 winners:
  impossible && !lastTurn → deadClaim × size
  impossible && lastTurn  → evSelf × endPts     # 終了点としては有効
  else                    → evSelf × EV

敵 sole 大型:
  → supplyOpp × size × P_opp_close   # 放置リスク
```

### 4.3 V_join / V_deny / V_minor

合流は `impossible` なら加点しない。  
妨害は `lag×denyBlock×size×ΔP_block`（係数は小さく）。  
修道院は `monasteryClaim`（今手で僧を置く）と埋め進捗。

**硬制約:** `masterExtra` 合計を `[extraNegCap, extraPosCap]` にクランプし、standard の即時点・修道院を覆さない。

### 4.4 重み（対standard弱さ対策後）

```js
master: {
  ...STANDARD,
  isMaster: true,
  equity: 0.35,
  gift: -0.35,
  enemyCompleteGift: -7.0,
  evSelf: 0.18,
  supplyOpp: -0.20,
  deadClaim: -2.5,
  joinOk: 0.25,
  joinFail: -0.50,
  joinCityMin: 3,
  joinRoadMin: 3,
  joinFieldMin: 2,
  lagRef: 12,
  denyBlock: 0.45,
  denyFatten: -0.35,
  monasteryPush: 0.85,
  monasteryClaim: 2.2,
  extraPosCap: 4.5,
  extraNegCap: -7,
}
```

## 5. standard との関係

standard も **lastTurn の温存ゼロ・畑解禁・タイブレーク** を共有する（融通は両レベル）。  
master だけ L2 期待点・合流・lag 妨害。

---

## 6. 受け入れ

1. lastTurn で skip より、完成都市付き畑／未完成都市の終了点が勝つ  
2. 手番が残るとき L2 不能都市への新規ミープルは負ける  
3. lag≈0 で純粋妨害が得点手に負け  
4. カタログ不能穴は `impossible`  
5. master 短試合が合法手のみ
